# Contributing to defold-tools

Thank you for taking the time. Please take it somewhere else.

It was made to solve the development problems of Lanterna Games. It is public the way
a workshop is public when its door is open: you may look, you may copy the idea, you
may walk off with the plans. You may not ask the people inside to build you one.

## Ways to help

| You have | Do this |
|---|---|
| A bug | Congratulations, it is yours now. Fork it and fix it there. |
| A mistake defold-vet reported that is not one | See above. It is a very good bug to own. |
| An idea for a new check | A lovely idea. Your fork will be the better for it. |
| A pull request | That is a fork with extra steps. Keep the fork, skip the steps. |
| A security problem | [SECURITY.md](SECURITY.md) explains how little will happen. |
| A question | The code is right there, and has never once been too busy to answer. |
| Praise | Accepted, in silence. |

## What happens to what you send

| You send | Expected response time |
|---|---|
| An issue | Between never and the heat death of the universe, whichever comes later |
| A pull request | The same, plus a rebase you will have to do yourself |
| "Any update on this?" | Resets the clock |
| A strongly worded follow-up | Resets the clock, and is admired for its prose |

Nothing personal. The mathematics are simple: the day has the usual number of hours,
and the games do not make themselves.

## If you fork it

Then you are the maintainer, and you have our sympathy. What you inherit is written
down, because it was needed written down:

- [Working on the code](docs/working-on-the-code.md): setting up, how the code is
  written, how a check is written, how commits are named.
- [The decisions](docs/decisions/README.md), each with its reasons, the ones that
  turned out wrong included.

`make check` will be yours too. It is strict, it is humourless, and it answers within
minutes, which is more than this page promises.
